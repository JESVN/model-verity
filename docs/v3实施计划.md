# model-verity V3 评分制验证与简化界面实施计划

> 状态：`pamela-scorecard@3.1.0` 与评分环分级色阶已部署生产，等待人工验收  
> 制定日期：2026-07-29  
> 核心研究基础：Bruckner/PAMELA 数据与方法（Zenodo record 21278557）  
> 针对性参考：canarybyte/veridrop（审计快照：2026-06-12，AGPL-3.0）  
> 发布原则：保持既有视觉风格和核心采样链路；评分是本次证据的可解释摘要，不是“模型为真的概率”。

## 1. 当前流程与页面结构审计

### 1.1 当前验证流程

1. 用户选择参考样本比对或实时双端配对。
2. 选择目标供应商、模型、目标协议和参考。
3. 手工填写 Vendor/Product/Surface，并选择 P1/P2/P3。
4. 选择 Quick/Audit/Full，批准固定请求与 token 预算。
5. 服务端固化 PAMELA challenge manifest，0 自动重试，逐请求原子占用预算。
6. 目标端采集 4/8/16 个 cell，每 cell 5/10/15 次；配对模式同步采集参考端。
7. 归一化单词/数字/颜色等答案，按 cell 构造经验分布。
8. 计算每 cell base-2 JSD、平均 JSD、覆盖率、bootstrap 区间、可选校准尾部证据。
9. 分析短时分组变化、响应 model 弱信号和失败情况。
10. 当前结果页展示行为、来源、稳定性、可比性、时效五维结论和多项统计细节。

### 1.2 当前问题

- 验证表单把内部身份建模和 P1/P2/P3 决策暴露给普通用户，步骤过多。
- 研究参考通常是 `surface=unknown`，导致大量 P3/未校准文案，用户难以形成直观判断。
- 结果页把五维状态、JSD、coverage、conformal tail、impostor risk、manifest hash 同时置于首屏，信息层级过重。
- “未校准”准确但不具备操作指导；用户要求一个稳定、透明、可理解的分数。
- 现有 JSD 不能直接当真实性概率，也不能用固定 0.12/0.22 阈值恢复旧误判。

## 2. VeriDrop 研究结论

### 2.1 实际流程

VeriDrop 按协议组织主动 detector 和被动 detector：主动 detector 发能力/行为请求；被动 detector 复用响应检查字段和事件流。单项输出 0–100 分，按权重加权；`skip` 不进入分母；critical issue 可把最终 verdict 上限锁在 marginal。UI 首屏显示总分、结论和简短检测项，技术证据折叠。

### 2.2 可吸收思路

1. **分数 + 等级 + 必要原因**的信息层级。
2. **维度权重公开**，结果可审计。
3. **不适用项不进入分母**，避免缺失能力被错误加分或扣分。
4. **严重问题设结论上限**，避免高均分掩盖关键失败。
5. **主动观测与被动观测复用**，协议/metadata 不必额外烧请求。
6. **技术详情默认折叠**，普通用户先看到可行动结论。

### 2.3 不直接采用

- 身份自报、知识题、品牌关键词容易被 system prompt 或包装层伪造。
- ID 前缀、字段形状和 model 字段主要证明兼容性，不证明来源；供应商可仿造。
- OpenAI/Gemini 没有通用加密回执，不能把协议高分写成真品概率。
- Claude thinking signature 只适用于特定 Anthropic 模型、协议和参数；当前通用 one-word PAMELA runner 不应静默加入高成本/高输出探针。
- VeriDrop 的 70/50 固定阈值和各协议权重没有替代本项目独立 calibration 的统计资格。
- 不复制 AGPL 源码、检测器实现、题库或 UI；只采用抽象设计原则。

## 3. V3 评分语义

### 3.1 名称

```text
综合可信评分：0–100
```

定义：对“本次目标服务声明得到多少可用支持”的透明摘要。它综合行为接近程度、采样质量、短时稳定性、请求可比性和参考强度。

它不是：

- 模型为真的百分比；
- 厂商认证；
- 密码学来源证明；
- 供应商整体信誉；
- 未来持续可用性保证。

### 3.2 维度与权重

| 维度 | 权重 | 输入 | 设计理由 |
|---|---:|---|---|
| 行为一致性 | 55 | PAMELA cell JSD；有匹配 calibration 时使用 genuine/impostor 分布校准 | 保持 Zenodo/PAMELA 为逻辑核心 |
| 请求质量 | 15 | 成功率 10；可比 cell 覆盖 5 | 防止低质量采样仍拿高分 |
| 短时稳定性 | 10 | block mixture、fallback、多个 model 声明、数据充分性 | 吸收 VeriDrop 的 consistency/critical cap，但不把 model 字段当身份 |
| 可比性 | 10 | P1=100、P2=70、P3=35 | 明确跨协议/产品面比较的降级 |
| 参考强度 | 10 | 来源等级与时效共同决定 | 防止旧研究参考被包装成官方基线 |

固定总权重 100。无 JSD 时整次结果为“无法评分”，不把缺失行为维度从分母移除；这是关键门禁，不采用对核心项 skip 后归一化。

### 3.3 行为分计算

#### 有匹配 calibration

以校准 artifact 的 `supportMax` 和 `anomalyMin` 做分段线性映射：

```text
JSD ≤ supportMax        → 90–100
supportMax < JSD < anomalyMin → 35–90
JSD ≥ anomalyMin        → 0–35
```

再由 impostor acceptance risk / genuine tail probability提供最多 ±5 的校准微调，但不会展示为真实性概率。

#### 无匹配 calibration

使用**展示映射**，不是统计错误率阈值：

```text
behaviorScore = 100 × (1 − JSD)
```

特性：JSD=0 时 100；0.17 为 83；0.23 为 77；0.35 为 65；0.52 为 48。JSD 本身是有界距离，因此线性反向映射最透明；它不宣称与真实性概率线性对应。该连续函数避免恢复已证伪的 0.12/0.22 二分阈值。结果必须标记 `uncalibrated=true`。

### 3.4 其他维度

```text
请求质量：successRate × 10 + coverage × 5

短时稳定性：
stable_window 100
possible_multi_serving 65
insufficient_data 55
behavioral_mixture 35
conditional_fallback 25
unstable 20

可比性：P1 100 / P2 70 / P3 35

参考强度基础：L1 100 / L2 75 / L3 45
时效乘数：current 1.0 / usable 0.85 / stale 0.55 /
           review_required 0.35 / quarantined 0 / superseded 0
```

### 3.5 等级阈值

| 分数 | 用户结论 |
|---:|---|
| 85–100 | 可信度较高 |
| 70–84 | 基本可信 |
| 50–69 | 需要复核 |
| 0–49 | 可信度较低 |
| 无行为分 | 无法评分 |

这些是产品展示阈值，不宣称 FAR/FRR 已校准。

### 3.6 结论上限（critical cap）

借鉴 VeriDrop 的“严重问题压制均分”，但使用本项目已有证据：

- P3：最高只能“需要复核”，即使数值分较高。
- L3 + stale：最高只能“需要复核”。
- `behavioral_mixture` / `conditional_fallback` / `unstable`：最高只能“需要复核”。
- success rate < 90% 或 coverage < 75%：最高只能“需要复核”。
- quarantined/review_required reference：最高只能“可信度较低”。
- 无匹配 calibration：禁止“可信度较高”；最高“基本可信”。
- 当前生产 policy 继续 `strongConclusion:false`。

数值分保持原始透明结果；`rawBand` 与 cap 后的 `band` 分开保存，UI 说明降级原因。这样不通过篡改分数隐藏问题。

## 4. 验证界面调整

### 4.1 默认核心流程

首屏只保留：

1. 顶部范围提示：“验证结果仅供参考，无法保证百分之百准确。”
2. 目标供应商。
3. 目标模型。
4. 参考样本。
5. 检测深度：快速 / 标准 / 完整。
6. 费用与请求上限摘要。
7. 启动按钮。

默认使用“参考样本比对”。供应商默认协议、模型 ID 和参考元数据自动决定协议、Vendor/Product/Surface、L/P 等级。

### 4.2 高级选项

“实时双端配对”及以下内容移入折叠的“高级验证方式”：

- 参考供应商与模型；
- 临时参考 Key；
- 两端协议；
- 两端声明 Vendor/Product/Surface；
- P1/P2/P3。

已有功能不删除；普通验证不必理解内部建模。

### 4.3 自动选择

- 选择参考后自动读取其 reference level、protocol、identity 和 freshness。
- 研究参考自动 P3；自建参考按身份/协议自动 P1/P2/P3。
- 目标模型改变时优先选择精确模型参考，其次保留当前可用参考。
- 用户不在普通模式手工提升等级。

## 10. GPT-5.5 低分解释与优化边界

生产存量记录 `cx/gpt-5.5` 的 76.7 分由以下部分组成：行为 83.2、质量 100、稳定性 100、P3 可比性 35、L3 stale 参考强度 24.8。它不是“模型为真的概率”。内置参考精确代表 2026-07-06 OpenRouter/OpenAI `gpt-5.5-20260423` serving 快照，不是所有官方 GPT-5.5 路径的统一模型本体。

该旧记录保留当时错误追加 marker 和错误 stale 状态对应的冻结 evidence，不得回写。新运行已修正 prompt 和时效。合理优化路径：

1. 使用修正后的内置参考重新 Audit；
2. 需要降低 cell/有限样本波动时使用 Full；
3. 建立同协议、同产品面、当前时间窗口的 L2 自建参考；
4. 有官方 OpenAI Key 时采用 L1 官方直连实时配对；
5. 收集独立 genuine/impostor 案例后建立匹配 calibration。

禁止通过提高基础分、放宽 P3/L3 cap、删除高 JSD cell、挑选好结果或把用户声明视为来源证明来提高分数。

## 11. 明确保留的统计边界

V3 的“可信度较高/基本可信/需要复核/可信度较低”是评分等级，不是预注册 1% FAR/FRR 强结论。只有未来匹配 calibration artifact 通过独立冻结集门禁后，才允许额外表达校准支持；当前生产继续禁止确定性来源结论。

## 12. 评分结果语义拆分（`pamela-scorecard@3.1.0`）

2026-07-30 保存运行 `915c3270-c2b2-44ec-b6a5-bf9192317b75` 的只读基线为：JSD `0.021452`、bootstrap `0.000330–0.052266`、80/80 请求成功、覆盖 100%、短时稳定、行为分 97.9、综合分 86.2。该运行的数值原始等级为 high；最终显示“需要复核”的唯一关键原因是内置研究参考强制 P3，另有无匹配 calibration 上限。它不是行为阈值拒绝，也没有观察到行为混合或质量不足。

`3.1.0` 不改权重、JSD 映射、等级阈值和 cap，而是修正信息合并错误：

- 仅受证据范围限制时，结果主数字使用行为维度分并命名为“行为相似评分”，综合证据分继续保留为次级审计值；基线运行因此显示行为相似评分 97.9（界面取整 98）和综合证据分 86.2；
- 行为分 ≥90 显示“行为高度相似”，70–89 显示“行为较为相似”；
- 仅当成功率 ≥90%、覆盖 ≥75%、短时状态为 stable/possible multi-serving，且 cap 只来自未校准、P3 或 L3 stale 时启用该拆分；
- P3 仍单独显示“来源证据待复核/比较范围待复核”，最终机器等级仍为 `review`；
- 低成功率、低覆盖、behavioral mixture、conditional fallback、unstable、参考治理失败或行为分不足继续使用原“需要复核/可信度较低”；
- 技术详情同时显示行为相似分、综合证据分、原始数值等级与范围限制后的等级；JSON 保留完整综合 `score`、主展示 `displayScore/displayScoreLabel`、`rawBand`、`band`、`caps` 和新 `scopeLabel`；
- `3.0.0` 历史记录不回写，前端只根据其冻结 scorecard 做等价的展示拆分；
- 主评分环颜色绑定当前展示指标而不是无条件读取机器 `band`：scope-only 双分数场景按行为相似评分使用 85/70/50 色阶；来源范围 badge 独立保持黄色。实质质量/稳定性 cap 的非 scope-only 结果继续按 cap 后 `band` 着色，避免高数字掩盖真实风险。

这项修改提高实际可读性，尤其适用于第三方网关与研究参考之间的跨 serving-stack 比较；它不会把行为相似升级为官方来源认证，也不通过放宽阈值掩盖第三方模型难以区分的问题。
