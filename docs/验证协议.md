# model-verity 综合服务声明验证协议

> 当前协议定义。内部 schema/API 为兼容保留实现细节，不是面向用户的产品版本标签。

## 1. 目标与边界

系统验证第三方 endpoint 的综合服务声明，将结果拆为：

1. 行为一致性；
2. 来源证据；
3. 服务稳定性；
4. 协议可比性；
5. 参考时效。

系统不提供厂商认证、密码学来源证明、模型身份概率或未来持续保证。行为相似只支持行为层面的证据。

## 2. 身份模型

```text
VendorIdentity
ProductIdentity
SurfaceIdentity: api | chatgpt | codex | enterprise | unknown
SnapshotIdentity
```

每个映射分开保存：

- `declared`：用户或供应商声明；
- `observed`：请求模型、响应 model、协议、usage 等直接观测；
- `inferred`：规则产生的弱候选。

`inferred` 不能覆盖声明、提升来源等级或单独进入确定性结论。

## 3. 参考等级

```text
L1：系统锁定官方 endpoint 的第一方直连
L2：用户指定可信 deployment
L3：研究、社区或本地参考
```

9router 等用户指定路径最多记录为 L2，不能由系统独立升级为 L1。

Reference version 不可覆盖。Freshness 和 quality 分开保存：

```text
freshness: current | usable | stale
quality: approved | review_required | quarantined | superseded
```

治理变化使用 append-only event。管理界面的四个状态操作按以下确定性转换，避免旧质量状态掩盖用户刚选择的新状态：

```text
确认仍可用：freshness=current，quality=approved
标记为过期：freshness=stale，quality=approved；仍不可用于新验证
标记为待复核：quality=review_required，保留当前 freshness
暂停用于验证：quality=quarantined，保留当前 freshness
```

每次转换都追加事件并返回转换后的 reference version；不会覆盖事件历史或修改旧验证记录。

## 4. 协议可比性

```text
P1：两端声明厂商、模型产品、非 unknown 产品面、请求协议、角色结构、参数语义和 challenge 一致
P2：两端声明厂商、模型产品和非 unknown 产品面一致，但协议或字段结构需语义映射，例如 Chat 与 Responses
P3：产品面未知/不同、产品声明不同、研究参考缺少同产品面元数据，或隐藏上下文无法对齐；只作诊断
```

服务端必须校验 P1/P2 的厂商、产品和产品面一致性；P1 额外校验协议相同。Adapter 不得在一次运行中静默切换协议。跨协议 control 只能用于诊断，不能用固定数值从其他 JSD 中相减。用户手工选择不能提升实际证据等级。

## 5. Challenge

Challenge 使用本地确定性模板生成，manifest 版本为 `pamela-challenge@2`，并显式保存 `promptMode`：

```text
fixed：原始任务表达 + 格式约束
marked：原始任务表达 + 格式约束 + 无语义 Request marker
```

适用范围：

- 内置 PAMELA 研究参考比对必须使用 `fixed`，因为 Zenodo 分布按原始固定 prompt 采集；不得向单边目标追加参考中不存在的 marker。
- 实时双端配对使用 `marked`，两端 system/user 字节完全一致。
- 自建参考采集使用 `marked`；后续与该版本比较时继续使用同一 marked protocol。

共同要求：

- 每个 challenge 有 ID、pair ID、block index、`promptMode` 和 SHA-256；
- marker 不改变任务语义；
- manifest 在运行开始后不可修改；
- 生成器不调用外部 LLM。

当前研究 battery 依据 Bruckner/PAMELA：10 个任务 × EN/RU/ZH/AR = 40 cells，`temperature=1.0`，one-word 可见答案，output limit 16。

## 6. 自建参考采集

自建参考必须通过 `reference enrollment plan` 执行，不接受直接提交任意 fingerprint 绕过采集。

流程：

1. 选择角色为 reference/either 的可信供应商、模型和明确协议；
2. 填写参考名称和 Vendor/Product/Surface；
3. 选择 L2 或 L3；用户路径不能自行声明 L1；
4. 创建逐批 request/input/output token 授权；
5. 运行固定 manifest，0 自动重试；
6. 质量门禁通过后，原子发布 reference cohort + immutable version；
7. 自动进入参考样本比对列表。

首期质量门禁：

```text
Quick：20 次请求，4 cells × 5
Audit：80 次请求，8 cells × 10
Full：240 次请求，16 cells × 15
请求成功率 ≥ 90%
可用 cells ≥ 75%，且至少 4
reasoning disablement 全部确认
必须完成冻结 manifest
```

失败、取消、预算不足、token stop-limit 或服务重启不会发布参考版本。参考版本被标记为 stale、review_required、quarantined 或 superseded 后不参与新的参考样本比对。

## 7. Pair runner

- 调度单位为 pair；
- 默认一个活跃 pair；
- Pair 内两端近同时启动；
- 启动顺序由 manifest seed 确定性随机；
- 保存实际 `startGapMs` 和 p95；
- Target/reference 独立限流和 adapter；
- 只有两侧均有效且时间差合格的 pair 才能进入最高等级跨端分析。

## 8. Observation 与 attempt

Observation 保存：

- challenge、pair、block、cell、repetition；
- request body hash；
- endpoint role 和 protocol；
- validity 和 normalized category；
- latency、usage、response model；
- pair completeness 和 start gap；
- reasoning 降级状态。

Attempt append-only。失败不能被覆盖；主分析使用每侧第一个有效响应，不能看答案后选择 attempt。

默认不保存：

- API Key；
- Authorization/Cookie；
- 完整 request headers；
- 敏感错误正文；
- 完整 raw response。

## 9. 归一化与经验分布

顺序：

1. 取可见文本；
2. Unicode NFC；
3. trim 和包裹标点清理；
4. 首答案提取；
5. case fold；
6. 多语言数字映射；
7. 颜色、coin 等任务 canonicalize；
8. 分类为 `valid | invalid | refusal | empty | error`。

经验分布只统计 valid category。低于最少有效样本的 cell 排除，不把缺失误判为行为偏移。

## 10. 距离与证据

每个可比 cell 计算 base-2 JSD：

\[
\mathrm{JSD}_2(p\|q)=H\left(\frac{p+q}{2}\right)-\frac{H(p)+H(q)}{2}
\]

并保留未加权平均 JSD。JSD ∈ [0,1]，只作为效应量。

校准证据可包括：

- observed distance；
- genuine bootstrap/posterior predictive distribution；
- genuine conformal p-value；
- impostor empirical distribution；
- impostor acceptance risk；
- cell/aggregate standardized evidence。

任何 p-value 都是尾部概率，不是“模型为真的概率”。

## 11. 综合可信评分

结果使用 0–100 的综合可信评分汇总本次证据：

```text
行为一致性 55%
请求质量   15%
短时稳定性 10%
可比性     10%
参考强度   10%
```

行为分继续以 PAMELA 每 cell base-2 JSD 为核心。有匹配 calibration 时按冻结 genuine/impostor 分布换算；没有匹配 calibration 时使用 `100 × (1 − JSD)` 作为透明的连续展示映射。后者不是错误率校准，也不是身份概率。

等级：

```text
85–100 可信度较高
70–84  基本可信
50–69  需要复核
0–49   可信度较低
无 JSD  无法评分
```

结论上限与数值分分开保存：P3、老化 L3 参考、低成功率、低覆盖、behavioral mixture、conditional fallback 或 unstable 最高只能“需要复核”；无匹配 calibration 最高“基本可信”；待复核、隔离或已替代参考最高“可信度较低”。评分不是厂商认证、真实性概率或未来保证。

`pamela-scorecard@3.1.0` 进一步拆分“行为接近程度”和“来源证据范围”：当行为分 ≥70、请求质量与覆盖达标、短时状态无降级，且最终等级只因 P3/未校准/研究参考时效受限时，主数字使用行为维度分并明确命名为“行为相似评分”，综合证据分保留为次级审计值；主结果显示“行为高度相似”或“行为较为相似”，并单独标记“来源证据待复核”。P3 cap 仍保留，不把研究参考或用户声明升级为来源证明，行为相似评分也不是官方来源概率。真实低覆盖、低成功率、行为混合、fallback 或较大 JSD 仍显示“需要复核/可信度较低”，不会被该展示规则放宽。

完整规则见 `docs/v3实施计划.md`。

## 12. 原始五维结论

### 行为一致性

```text
行为相容迹象 | 合理漂移 | 需要复核 | 行为偏移 | 未校准
```

### 来源证据

```text
未验证 | 用户声明参考 | 第一方配对支持 | 可验证回执
```

### 服务稳定性

```text
窗口内稳定 | 波动 | 可能多路 serving | 条件 fallback | 数据不足
```

### 协议可比性

```text
严格可比 | 语义可比 | 不可比
```

### 参考时效

```text
current | usable | stale | review_required | quarantined
```

Rolling product 和内置研究参考的默认时间规则：

```text
0–14 天：current
15–45 天：usable
超过 45 天：stale
```

时间从参考的 `collectedAt/enrolledAt` 计算；无效或未来时间 fail-closed 为 `stale`。Exact snapshot 可保留用于历史快照比较，但行为时效仍单独展示。治理状态 `review_required/quarantined` 不由时间自动解除。

当前数据尚未证明：

```text
行为支持的 impostor 误接收率 ≤ 1%
明显异常的 genuine 误拒绝率 ≤ 1%
```

因此生产不输出未经独立校准支持的确定性强结论。

## 13. 动态路由检测

按以下字段分组分析：

- reported model；
- block/time；
- latency；
- usage；
- attempt；
- error；
- normalized category。

识别：

```text
stable_window
possible_multi_serving
behavioral_mixture
conditional_fallback
insufficient_data
```

单个 `model` 字段变化不决定结论。

## 14. 预算

每次运行先授权：

- 供应商和模型；
- 最大 pair；
- 最大 endpoint requests；
- 最大 attempt；
- 最大 input/output tokens；
- 有效期。

请求发出前原子 reserve。Provider 返回 usage 后原子累计 token；超限时停止后续请求。自动测试、build、部署和 CI 不调用真实供应商。

## 15. 临时凭据

- 默认只保存在内存；
- 绑定 run ID 和 endpoint role；
- 默认 15 分钟，最长 60 分钟；
- 完成、失败、取消、过期或 shutdown 后删除；
- 不写磁盘、SQLite、History、日志或导出。

## 16. 报告

JSON、Markdown、CSV 和时点分享报告必须包含证据范围、时间、预算和 endpoint binding；不得包含 Key、query、fragment、userinfo 或原始 endpoint secret。报告不是厂商认证或未来保证。
