## 1. 协议是否会造成大偏移

Chat Completions 和 Responses 的 JSON 结构不同：

- Chat 使用 `messages` 和 `max_tokens`。
- Responses 使用 `instructions`、`input` 和 `max_output_tokens`。
- 网关可能为两种协议选择不同 serving stack、隐藏上下文或 usage 口径。

但“协议不同”不意味着必然出现大行为偏移。为隔离协议因素，在同一个 9router endpoint、同一个 `cx/gpt-5.6-sol`、相同 4 cells × 5 repetitions 下分别调用 Chat 与 Responses，共 40 次请求：

```text
跨协议平均 JSD：0.058136
Chat valid：20/20
Responses valid：20/20
Chat 返回 model：gpt-5.6-sol ×20
Responses 返回 model：缺失 ×20
reasoning degraded：两边均 0
input tokens：18,144
output tokens：267
```

分 cell：

| Cell | JSD |
|---|---:|
| `en:word-random` | 0.000 |
| `ru:city-random` | 0.125 |
| `zh:animal-random` | 0.108 |
| `ar:color-random` | 0.000 |

这说明在 9router 当前路径上，Chat/Responses 映射本身带来小到中等有限样本差异，但不足以单独解释此前 AiCodeWith 相对 9router 的 0.291/0.366。剩余偏移可能来自 endpoint serving context、产品面、请求 token 口径、样本无效/预算污染或真实行为差异，不能仅归因于协议。

## 2. 如何消除协议歧义

不能用一个全局常数从 Responses JSD 中“减去协议差异”，因为 JSD 非线性，协议影响也按模型、cell 和 endpoint 变化。

采用以下规则：

1. 每个 endpoint 可以为本次 paired run 显式选择协议，不再被供应商保存协议锁死。
2. 若两端都支持共同协议，优先使用同一协议，标记 P1 候选。
3. 若只能 Chat ↔ Responses，标记 P2，并使用该模型/endpoint 的 crossover control。
4. Crossover control 使用同一可信参考 endpoint 同时跑 Chat 和 Responses，估计协议基线与方差。
5. 正式统计比较协议条件分布或标准化超额偏移，不直接比较一个未校准原始 JSD。
6. 没有相应 crossover calibration 时，P2 只能输出探索性相容/偏移，不输出强档位。
7. 返回 `model` 字段差异仍只作为弱信号；本次 Responses 缺 model 就证明不能把它作为协议一致性的硬门禁。

本轮代码已支持从 run 的 `identity.observed.targetProtocol/referenceProtocol` 固化实际 adapter；API 阻止不同协议冒充 P1。

## 3. 零费用本地安全测试

新增 mock 测试：

- 同一受控 provider 的 Chat/Responses 可见行为映射一致。
- 返回 model 固定不变时，按 block 改变答案仍检测 `behavioral_mixture`。
- 429 不由 adapter 自动重试，保持一次计费请求。
- 并发预算 reservation 只允许批准数量成功。
- Token stop-limit 超限必须 fail-closed，不能伪装成 endpoint error。
- Retry 样本行为变化检测 `conditional_fallback`。
