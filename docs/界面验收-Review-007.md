## 用户问题

旧表单把“参考端模型 ID、模型列表获取、参考名称、声明的模型产品”等不同性质的信息平铺为同级字段。用户无法判断哪些是请求路由、哪些是上游身份声明、哪些只影响列表显示，并被迫重复填写相近内容。

## 根因与修复

- 模型 ID 是发送给 API 的原始路由字符串；上游模型是用户声明该路由代表的模型身份。两者不能在数据层合并，但必须在界面上明确区分。
- 表单改为“从哪里采集 / 这份参考代表什么 / 选择采集规模”三段，先显示普通语言，再保留报告所需字段。
- 模型列表获取合并到模型 ID 控件；远程返回但未配置的模型显示为“未配置”且不可选，避免启动后才被服务端 allowlist 拒绝。
- 上游模型默认与模型 ID 联动；只有点击“模型 ID 是别名，修改”后才显示独立输入，人工修改后不再被模型选择覆盖。
- 参考显示名称按供应商、上游厂商/模型和月份自动生成；自定义名称收入高级设置，仍只用于显示、不参与评分。
- 请求协议默认继承供应商配置；协议覆盖和临时 API Key 收入高级设置。
- 固定 `OpenAI` 默认声明已移除；切换供应商会清除旧上游厂商，产品形态默认推荐 API 接口但仍可按真实路径修改。
- 启动前增加请求路径、上游声明、产品形态和 L2/L3 摘要。

本次不改变数据库 schema、评分、参考质量门禁、20/80/240 请求预算、0 自动重试、manifest 或证据等级。

## 人工验收清单

1. 打开“参考样本”，点击“创建参考样本”，确认表单分为三个编号步骤，没有旧的十字段平铺感。
2. 确认“发送给接口的模型 ID”与“实际上游模型”含义清楚；对 `cx/gpt-5.6-sol` 点击“模型 ID 是别名，修改”，可填写 `gpt-5.6-sol`。
3. 修改过上游模型后再切换模型 ID，确认人工填写值不会被覆盖；点击“与模型 ID 相同”可恢复联动。
4. 点击“刷新模型列表”，确认已配置/未配置状态清晰；未配置模型不能直接用于启动。
5. 确认“实际上游厂商”不再固定预填 OpenAI；切换供应商后旧厂商声明被清除。
6. 确认产品形态说明能判断普通 API 网关、ChatGPT、Codex、企业部署和无法确认。
7. 确认参考名称自动生成；展开高级设置后可以自定义显示名称、覆盖协议或填写临时 Key。
8. 确认启动前摘要能同时核对请求模型 ID、上游模型声明、产品形态和参考等级。
9. 在 320–430px 窄屏确认无水平溢出，模型按钮、别名按钮、Select 和启动按钮触控目标清晰。
10. 用键盘遍历表单和高级设置，确认焦点可见；reduced-motion 下无新增循环动画。
