## 用户问题

参考样本页原先把创建入口、参考组/版本数量、版本选择、四个治理操作、研究搜索和研究列表平铺在连续页面中。标题、说明、按钮和字段缺少明确容器关系，用户难以区分“创建自建参考”“管理已有版本”和“搜索研究参考”三个任务。

## 根因与修复

- 页面信息架构改为两个独立卡片：自建参考和公开研究样本库，不再把两类来源及其操作平铺在同一层级。
- 自建参考卡先展示参考组/版本数量、创建入口和不可覆盖已有样本的说明。
- 已有版本集中到独立治理区域；选择版本后直接显示当前时效和质量状态，再提供状态更新操作。
- 治理操作明确说明只影响后续验证，不修改旧记录；确认可用与限制类操作使用不同视觉层级。
- 研究搜索移入研究参考库卡片，与匹配数量、结果列表和分页保持同一上下文。
- 720px 以下标题、统计、状态和创建操作切换单列；600px 以下主操作占满可用宽度，避免窄屏挤压。
- Review #007 的三步创建表单、模型 ID/上游声明分离、远程 allowlist、自动名称和高级设置语义保持不变。

本次不改变数据库 schema、API、评分、参考质量门禁、20/80/240 请求预算、0 自动重试、manifest、证据等级或既有记录。

## 人工验收清单

1. 打开“参考样本”，确认“自建参考”和“公开研究样本库”是两个边界清楚的独立卡片。
2. 确认自建参考卡顶部先看到参考组/版本数量和“创建参考样本”，不会与版本治理按钮混成同一行。
3. 确认“已有版本”区域按“选择版本 → 查看当前状态 → 更新状态”的顺序展示。
4. 切换不同版本，确认“当前状态”的时效、质量和解释随选择更新，长模型名称不会挤压或溢出。
5. 确认“确认仍可用”视觉上是主要治理操作，“标记为过期 / 待复核 / 暂停用于验证”保持次级操作；文案明确不修改旧记录。
6. 确认研究搜索位于“公开研究样本库”卡片内；输入模型名称后匹配数量、列表和分页同步更新。
7. 点击“创建参考样本”，确认 Review #007 的三个编号步骤、模型 ID 与上游模型区分、自动名称和高级设置仍正常；不要启动真实采集。
8. 在 320–430px 窄屏确认统计卡、状态说明、版本操作、研究列表和分页无水平溢出，主要触控目标至少 44px。
9. 用键盘遍历创建入口、版本 Select、治理按钮、研究搜索和分页，确认焦点可见且顺序符合视觉层级。
10. 在 reduced-motion 下确认没有新增循环动画；取消创建后回到整理后的版本治理卡片。
