# model-verity 当前界面规范

> 当前生产基线：2026-07-28 全新界面  
> 设计原则：克制、即时反馈、清晰层级、可撤销导航、无伪精确结论

## 1. 产品语言

当前 UI 不显示：

- 内部 schema/API 代际；
- 探索模式或候选标签；
- Legacy、旧版、新版等迁移标签；
- Audit/Enrollment 暂停说明；
- 内部 framework/policy 名称。

当前 UI 必须显示必要的证据边界：

- 结果不是厂商认证；
- 结果不是模型身份概率；
- 行为相似不证明来源；
- 长期稳定性未评估时不能暗示未来保证；
- 未匹配 calibration 时明确显示未校准或需要复核。

## 2. 全局布局

导航：

```text
验证
供应商
参考样本
历史
```

### 桌面 ≥1100px

- 顶栏和侧栏固定；
- 仅主内容区滚动；
- 主内容最大宽度约 760px；
- 验证卡最大宽度约 640px。

### 窄屏 <1100px

- 导航改为顶部横向滚动；
- 主内容单列；
- 320–430px 不得出现水平溢出；
- 主要点击目标至少 44×44px。

### 视觉

- 固定深色主题；
- 48px 低对比暖橙网格背景；
- 深棕灰卡片、细边框、克制阴影；
- 暖橙用于主操作和当前导航；
- 红色仅用于危险删除，不用于未经校准的行为偏移；
- system-ui 字体，标题负 tracking，正文保持舒适行高；
- 正文和字段说明默认不小于 13px，历史摘要等高频信息使用 13px、至少 1.55 行高和中等字重；
- 11–12px 仅用于短 badge、状态或专业元数据，不承载关键操作说明；
- 主要深色卡片上的次要文字对比度至少 7:1，弱辅助文字至少 5.5:1，状态色和品牌文字至少 4.5:1；
- 暖橙主按钮使用深色文字，按下态切换为深橙底和白字，确保各状态文字对比度达标。

## 3. 验证页

首次进入时必须先完成供应商、参考样本和历史数据加载，再显示可操作表单，避免空选项闪现或覆盖用户偏好。选择规则：

- 当前浏览器没有已保存偏好时，依次选择第一个可用于验证的供应商、该供应商的第一个模型和第一个参考样本；没有对应数据时保持空值并显示可操作提示；
- 用户修改供应商、模型、参考样本、检测深度或高级验证配置后，立即保存在当前浏览器，刷新后恢复；
- 已保存的供应商、模型或参考不再可用时，回退到当前第一个可用项；History“再次验证”仍按历史资源缺失规则 fail-closed，不得被浏览器偏好静默替换；
- 临时 API Key、预算授权、credential session、运行结果和密钥不得进入浏览器表单偏好。

标题：

```text
综合服务声明验证
```

说明必须同时覆盖五个维度，并明确不是身份概率或认证。

### 3.1 验证方式

```text
参考样本比对
实时双端配对
```

### 3.2 目标配置

- 第三方供应商；
- 第三方模型；
- 第三方请求协议；
- 声明厂商；
- 声明产品；
- 产品面。

### 3.3 参考样本比对

- 显示可搜索参考样本 Select；
- 参考来源分组：自建参考与研究参考不混在同一平铺列表，上方提供“全部 / 自建参考 / 研究参考”来源筛选并显示各自数量；
- 参考来源 badge 可见；切换来源筛选后自动选中该来源下最匹配的参考；
- 无可用参考时明确提示切换实时双端配对或选择有研究参考覆盖的模型；
- 不自动生成或伪造参考。

### 3.4 实时双端配对

- 参考 endpoint；
- 参考模型；
- 参考请求协议；
- 可选临时第一方 API Key；
- 临时 Key 说明必须明确：仅内存、绑定本次运行、结束/取消/过期/重启销毁。

### 3.5 产品面与协议可比性

产品面字段必须显示中文选项和就地解释：

```text
API 接口：普通模型 API 或 API 中转
ChatGPT 产品：网页/应用产品面，可能带隐藏上下文
Codex 编程产品：编程代理产品面
企业专属部署：租户、专属 deployment 或组织级配置
无法确认：信息不足，按最保守范围处理
```

协议可比性必须显示“定义、何时选择、对结果的影响”：

```text
P1 条件一致：两端厂商、模型产品、产品形态、协议和采样问题一致
P2 协议不同：厂商、产品和产品形态一致，但 API 协议或字段结构不同
P3 仅看行为：产品形态未知/不同、产品不同，或隐藏设置无法对齐
```

界面先显示普通语言标签，再保留 P1/P2/P3 代码供报告核对。每项说明都要写清适用条件和结论影响；P3 仍可比较回答行为，但不能确认实际上游来源。

- 默认按当前目标和参考元数据推荐等级；
- 研究参考默认 P3；
- 任何一端产品面为“无法确认”时只能推荐 P3；
- P1/P2 要求两端厂商、产品和非 unknown 产品面一致；
- P1 额外要求协议一致；
- 前端即时说明，服务端再次拒绝不满足条件的 P1/P2；
- 手工选择只能降低，不能提升实际证据等级。

### 3.6 预算

档位：

```text
Quick · 20 组样本
Audit · 80 组样本
Full · 240 组样本
```

启动前显示：

- 最大样本组；
- 最大 endpoint 请求；
- input/output token 上限；
- 自动重试策略；
- 预算不会自动扩大；
- 真实请求可能产生费用。

主按钮使用具体数量：

```text
批准并启动最多 N 次请求
```

## 4. 运行页

必须显示：

- 真实进度；
- 当前阶段；
- 成功和失败计数；
- 已用时间；
- 最大请求；
- Pair 近同时启动和随机先后说明；
- 取消按钮。

取消后立即反馈，不等待动画完成。运行状态由服务端决定，刷新和多标签页不能伪造完成状态。

## 5. 结果页

顶部使用综合摘要，不使用“可信度百分比”。

五维卡片：

1. 行为一致性；
2. 来源证据；
3. 服务稳定性；
4. 协议可比性；
5. 参考时效。

结果上下文必须区分：验证完成页显示“返回验证”；History 内独立结果页显示“历史验证结果”和“返回历史记录”，不得通过切换到验证导航复用页面状态。“再次验证”才切换验证页。

技术信息：

- 原始平均 base-2 JSD；
- 可比 cell 覆盖；
- genuine conformal p-value；
- impostor acceptance risk；
- 使用预算；
- manifest version、`promptMode` 和 hash；
- limitations。

统计参数放在技术详情，不抢占结论层级。P-value 不称模型为真的概率。

导出操作：

```text
JSON
Markdown
CSV
创建 7 天时点报告
```

## 6. 供应商页

支持：

- 添加供应商（页内表单）和编辑供应商（独立弹窗）；
- OpenAI Chat、OpenAI Responses、Anthropic Messages；
- API Key 密码输入；
- 模型 ID 手工输入；
- 从 Base URL 获取模型列表；
- 最小连接测试；
- 删除确认。

编辑供应商必须弹出独立对话框，与“添加供应商”表单分开，避免在添加区域直接修改已有供应商造成误解。连接测试结果只表达当时连接可用，不证明身份。删除供应商使用统一红色垃圾桶和应用内确认对话框。

## 7. 参考样本页

- 页面标题使用“参考样本”；
- 自建参考与研究参考使用两个独立卡片分区，不把创建、版本治理、研究搜索和研究列表平铺在同一层级；
- 自建参考卡先显示参考组/版本数量和“创建参考样本”，已有版本的选择、当前时效/质量状态及治理操作收在同一治理区域；
- 当前可用使用绿色、仍可使用使用柔和绿、已过期使用黄色、待复核使用品牌橙、已暂停/已替代使用中性灰；状态必须同时显示文字、圆点、时效/质量 badge，不能只依赖颜色；
- 版本治理按钮使用单选式选中反馈和 `aria-pressed`；点击后立即更新当前状态并锁定其他操作，服务端失败时回滚，成功后以服务端返回版本校正；
- 研究搜索放在研究参考库卡片内，与筛选数量和结果列表保持同一上下文；
- 首屏提供“创建参考样本”，即使当前没有任何自建版本也必须可见；
- 创建表单按“从哪里采集 / 这份参考代表什么 / 选择采集规模”分组，不把请求路由、上游声明和显示名称平铺为同级字段；
- “发送给接口的模型 ID”保存实际请求字符串；“实际上游模型”保存用户声明的模型身份。两者默认联动，模型 ID 是网关别名或带路由前缀时才展开修改，人工修改后不得被后续模型选择覆盖；
- 模型列表获取合并到模型 ID 控件，不独占业务字段；远程返回但未加入供应商配置的模型不得绕过服务端 allowlist 启动采集；
- 参考显示名称按供应商、上游模型和月份自动生成，只影响列表显示；自定义名称、协议覆盖和临时 Key 收入高级设置；
- 上游厂商不得固定预填为 OpenAI；切换供应商时清除旧上游声明，避免静默生成错误身份；API 参考默认推荐“API 接口”，但用户仍需按网关实际连接的产品形态确认；
- 选择可信供应商、模型、Vendor/Product/Surface 和 L2/L3；常规协议继承供应商配置，必要时可在高级设置覆盖；
- 启动前显示请求路径、上游声明、产品形态和来源等级摘要；
- 显示 20/80/240 次请求预算、token 上限、0 自动重试和质量门禁；
- 临时 Key 明确仅存内存；
- 运行中显示真实进度、成功/失败和取消；刷新及多标签可恢复；
- 完成后显示版本 ID、质量、等级，并自动接入验证页参考下拉；
- 失败或取消不发布版本；
- 展示版本化参考治理，可确认可用、标记过期、需要复核或暂停使用；
- 研究参考库支持搜索和分页；
- 研究和自建参考均明确不构成厂商认证；
- 不显示 Enrollment、暂停或旧框架说明。

## 8. 历史页

- 全新数据状态初始为空；
- 空状态：`暂无验证记录。`；
- 新记录显示供应商、模型、时间、验证方式、状态和行为摘要；
- 点击进入完整结果；
- 结果页“再次验证”返回验证表单，并带入该记录的验证方式、目标供应商/模型、参考样本或参考端、检测深度、协议和身份声明；
- 已删除或停用的供应商、模型、参考不静默替换，必须提示用户重新选择；API Key、旧预算授权和临时凭据不得从历史恢复，启动前仍需重新确认预算；
- 可删除已完成记录；
- 活跃记录不可删除；
- 删除使用应用内确认，并说明 observations/evidence/share report 会级联删除。

## 9. 数据与隐私说明

不设置独立静态页面。说明放在对应操作附近：

- 供应商页说明 API Key 加密保存；
- 实时双端配对说明临时第一方 Key 仅内存；
- 验证页说明完整响应默认不保存；
- 历史页提供结果删除；
- 稳定性结果说明不会自动执行长期监控。

## 10. 对话框

危险操作确认：

- 44×44px 红色垃圾桶；
- 默认焦点在取消；
- `Escape` 和遮罩可取消；
- 焦点锁定；
- 提交期间禁止关闭；
- 错误在对话框内原位显示；
- 不使用 `window.confirm`。

## 11. 动效与无障碍

- 全局复用 `LoadingState` 表达首次数据同步；根数据、参考治理数据和上次运行恢复均使用一致状态文案和动画；
- 加载状态使用 `role=status`、`aria-live=polite` 和 `aria-busy=true`，不能只靠动画表达；
- 默认动画只改变 `transform` 和 `opacity`，不阻塞导航；`prefers-reduced-motion` 下停止循环动画并保留静态状态标识；
- Pointer down 立即有 press feedback；
- 普通切换使用短 opacity/translate 反馈；
- 动效不阻塞输入；
- `prefers-reduced-motion` 下取消位移、脉冲和循环动画；
- `prefers-reduced-transparency` 下使用更实的表面；
- 键盘可遍历；
- Select 具备 combobox/listbox ARIA；
- 焦点环可见；
- 信息不只依赖颜色。

## 12. 评分制验证首屏

验证页顶部必须显示：

```text
验证结果仅供参考，无法保证百分之百准确。
```

默认验证首屏只保留供应商、模型、参考样本、检测深度、预算摘要和启动按钮。实时双端配对、协议覆盖、Vendor/Product/Surface 和临时参考 Key 收入“高级验证方式”，保留功能但不阻塞普通用户。

结果页首屏按顺序显示：

1. 0–100 评分；常规场景显示综合可信评分；若高行为相似度仅受 P3 研究参考范围限制，则主数字显示“行为相似评分”，并在同一卡片保留较小的综合证据分；
2. 可信度较高 / 基本可信 / 需要复核 / 可信度较低 / 无法评分；范围受限场景拆分显示“行为高度/较为相似”与“来源证据待复核”，不能把来源限制误写成行为不相似，也不能把行为分写成官方来源概率；
3. 主评分环按当前展示指标分级：85–100 使用明确绿色，70–84 使用较克制的柔和绿，50–69 使用黄色，0–49 使用红色，无分使用灰色；颜色必须同时有分数和文字，不单独承载结论；
4. 当主数字是行为相似评分时，评分环按行为分着色，来源证据 badge 独立保持黄色；低质量、低覆盖、行为混合等实质 cap 不得借行为分变绿，仍按 cap 后等级着色；
5. 一句话结论；
6. 最多三条关键说明；
7. 五项评分组成。

JSD、bootstrap、校准尾部统计、原始五维状态和 manifest hash 默认收入“查看技术详情”。评分必须明确不是模型真实性概率或厂商认证。既有颜色、卡片、圆角、字体、按钮和动效系统保持，不整体重构风格。

## 13. 术语解释门禁

当前主流程中的每个非日常术语必须同时提供：

1. 它是什么；
2. 用户如何选择或系统如何判断；
3. 选择会如何影响请求、费用或结论。

说明先用普通语言，再在需要核对报告时保留专业缩写。默认字段说明控制在一句话内，避免页面说明、字段帮助、Select 副说明和结果详情重复表达同一边界；需要展开的细节留在 Select 或技术详情。优先使用“产品形态”“问题组合”“有效问题覆盖”“同源样本尾部比例”“异源样本误接近比例”等直白名称；必要时用一个短示例说明。至少覆盖：验证方式、供应商角色、请求协议、模型 ID、声明厂商、声明产品、产品形态、P1/P2/P3、L1/L2/L3、采样预算、token、参考时效、参考质量、五维结论、JSD、有效问题覆盖、校准、重复抽样区间、同源样本尾部比例、异源样本误接近比例和采样清单校验值。内部状态码不得作为唯一用户文案。
