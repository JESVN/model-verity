## 发现并修复的问题

1. tsup 将 keytar Linux `.node` 二进制打入包，破坏跨平台安装；改为 external runtime dependency。
2. server 关闭时先关 DB，后台 run 可能继续写库；改为先 abort/wait runs，再关 HTTP/DB。
3. 服务重启遗留 `queued/running`；启动时恢复为 `failed` 并说明中断原因。
4. `retainRaw` 只存在设置但未持久化；现在按开关保存 Enrollment/Audit raw samples。
5. Enrollment 低成功率/有效 cell 不足仍可建立参考；增加可信参考质量门槛。
6. 熔断未为所有跳过样本计 error，且 error 计数按 cell 去重；改为逐 sample 完整计数。
7. API Key fallback 派生材料可预测；改为随机 256-bit `master.key`（0600）或显式主密钥。
8. keytar 可加载但运行失败时没有回退；增加运行失败自动转加密文件。
9. OpenAI-compatible 严格网关可能拒绝 reasoning 扩展字段；遇明确 400 时无字段重试并标记协议降级。
10. 返回 thinking/reasoning 时仍声称已关闭；OpenAI/Anthropic 均检测并降级，禁止给绿。
11. Reference 未核验 system prompt 版本；加入 battery/normalize/system 三版本一致性检查。
12. Provider/Reference 可在活动 run 中删除；API 改为 409 拒绝。
13. Provider 删除会级联删除参考/损坏 History；改为软删除并保留历史关联。
14. 多 run 同时启动可突破全局并发预算；当前 v1 限制同一时刻一个 active run。

## 2026-07-27 Review #005 对抗式检查

### 第一性原理模型

1. **删除安全**：图标只是入口；防误删的必要条件是明确对象与影响、默认取消、二次提交、失败不丢上下文。浏览器 `window.confirm` 不可控，因此替换为应用内 `alertdialog`。
2. **任务恢复**：服务端 run 是事实；浏览器 track ID 只定位用户正在关注的 run；当前 History 详情是第三种独立状态。三者混为 `activeRun` 会导致切页后丢采样页。
3. **连接测试**：`/models` 不能证明推理可用；最小真实推理可以覆盖网络/鉴权/协议/解析，但不能证明身份，因此不写 History、不纳入 JSD，并与采样互斥。
4. **结果可解释性**：可信度由距离门槛与证据质量共同决定。只显示颜色/分数无法回答“为何”；必须固化运行时判定快照，区分决定性原因与质量条件。
5. **部署安全**：生产切换必须先阻止新任务、等待现有任务、隔离 smoke、备份并可自动回滚；维护状态必须由本机锁文件控制而不是公网写 API。

## 2026-07-27 9router 进度条卡住追加检查

### 第一性原理

验证进度条不是网关后台状态，而是浏览器 state 中 `activeRun.progress` 的投影。真实数据链路是：

```text
adapter 请求完成 → executor onProgress → SQLite updateRun(progress) → GET /api/runs/:id → React setActiveRun → RunningPanel
```

9router 后台收到并完成请求，只证明链路前半段有效；进度条不动但刷新后更新，证明 SQLite 已有正确状态，问题在前端轮询结果没有写回当前渲染 state，而不是供应商请求未完成。

### 根因

前端轮询原逻辑只在 `viewRef.current.runId === id` 时更新 `activeRun`。在某些导航/恢复/历史切换路径中，`activeRun` 仍是正在看的 run，但 `view.runId` 可能暂时为空或不是同一个 ID。此时轮询虽然拿到了最新 run，也更新了 `runs` 列表，却没有更新 `activeRun`；`RunningPanel` 继续渲染旧对象。刷新页面后初始恢复从服务端重新取 run，所以立刻显示完成。

其他供应商不明显，是因为它们的请求节奏让导航状态更常停留在匹配的 `runId` 路径；9router 完成速度或响应聚合方式更容易暴露该 UI 状态门控缺陷。

### 修复

- 新增 `activeRunRef` 保存当前渲染中的 run。
- 轮询到最新 run 后，只要 `view.runId === id` **或** `activeRun.id === id`，都写回 `setActiveRun(run)`。
- 保持 History 查看无关 run 时不覆盖当前详情；只有同一个 active run 才更新。
