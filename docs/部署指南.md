# 部署指南——安装、启动、停止与数据目录

> 本文同时记录本机生产部署实况与通用安装方式。当前 npm 发布版本：`model-verity@0.1.0`；生产站运行未发布的 Review #009 候选（内部版本字段仍为 `0.1.0`，npm 发布需单独批准）。

---

## 1. 环境要求

- Node.js **≥ 20**（建议 LTS）  
- npm **≥ 10**  
- 桌面浏览器（Chrome / Edge / Firefox / Safari 近两年版本）  
- 可选：系统钥匙串（macOS Keychain / libsecret 等）以启用 K4 最优路径  

---

## 2. 安装

### 全局（已发布）

```bash
npm install -g model-verity@0.1.0
model-verity --version
model-verity --help
```

### 开发目录（当前仓库）

```bash
cd /root/projects/model-verity
npm install --include=dev   # NODE_ENV=production 时必须显式安装 devDependencies
npm run typecheck
npm test
npm run build:library  # 仅维护者：从本地 PAMELA 源数据重建内置库
npm run build          # 构建 CLI + server + web，并复制内置库资产
npm run preview:ui     # 仅 UI Preview Lab（开发门禁）
npm link               # 可选：本地全局链接 CLI
```

---

## 3. 启动本地 Web

```bash
model-verity start
```

预期输出示例：

```text
model-verity listening on http://127.0.0.1:8787
data directory: ~/.config/model-verity
press Ctrl+C to stop
```

常用参数：

```bash
model-verity start --port 9000
model-verity start --host 127.0.0.1   # 默认；勿默认 0.0.0.0
```

打开浏览器：

```bash
model-verity open
# 或手动访问打印的 URL
```

## 4. 状态与停止

```bash
model-verity status
# → running | stopped, pid, url, dataDir

model-verity stop
# 若为前台 start：在该终端 Ctrl+C
```

v1 CLI 默认前台运行。当前服务器使用 systemd 托管，见下文生产部署章节。

## 5. 当前服务器生产部署

### 5.1 systemd 服务

```bash
systemctl status model-verity
systemctl restart model-verity
journalctl -u model-verity -f
```

实际路径：

| 项 | 路径/值 |
|----|---------|
| Node.js | `/opt/node-v22/bin/node`（v22.23.1） |
| npm 包 | `/opt/model-verity/lib/node_modules/model-verity` |
| systemd unit | `/etc/systemd/system/model-verity.service` |
| 数据目录 | `/var/lib/model-verity/config/model-verity` |
| 监听地址 | `127.0.0.1:8787`（仅供本机反代） |
| 公网域名 | `https://modelverity.example/` |
| NPM Proxy Host | ID 9，转发到本机生产监听地址 |

服务设置了 `Restart=on-failure`、专用非特权用户 `model-verity`、`UMask=0077` 与 systemd 沙箱限制。

### 5.2 公网访问保护

生产域名当前启用了：

- HTTP → HTTPS 301
- Let's Encrypt TLS
- Nginx Proxy Manager Basic Auth；未认证 HTTPS 请求返回 401
- 认证通过后反代到仅监听 `127.0.0.1:8787` 的应用服务
- 应用自身不管理公网账户；任何通过 Basic Auth 的客户端都可调用应用 API，包括触发付费请求、修改供应商和删除数据

Basic Auth 曾于 2026-07-30 按用户要求解除，用户于 2026-08-03 确认已由其自动恢复。凭据不得写入项目文件、日志或命令历史。部署脚本只更新应用安装目录和 systemd 服务，不修改 Nginx Proxy Manager 的认证配置。


### 5.4 当前生产部署门禁

本轮使用 root-only 自动部署脚本，不发布 npm，也不调用真实供应商：

```bash
sudo ./scripts/deploy-production.sh
```

脚本顺序：

1. 在数据目录创建带会话 ID 的 `maintenance.json`，服务端继续现有任务，但拒绝新采样、连接测试以及供应商/参考删除；普通浏览、历史导出/删除和供应商表单保存保持可用。
2. 执行 typecheck、当前全量测试（Review #009 为 68 tests）、build、production dependency audit。
3. 候选在独立 `127.0.0.1:18787` 与隔离数据目录启动，检查 health、API、SPA、证据策略和旧写 API 410。
4. 最多等待活跃采样/连接测试 30 分钟；超时停止部署，不强制取消。
5. 备份当前安装目录、数据目录和 systemd unit。
6. 切换生产并检查 upstream；失败自动恢复旧安装和 unit。
7. 只删除本会话创建的维护锁。

可通过环境变量覆盖 `INSTALL_DIR`、`DATA_DIR`、`MODEL_VERITY_PRODUCTION_HOST`、`MODEL_VERITY_PRODUCTION_PORT`、`MODEL_VERITY_CANDIDATE_PORT`、`WAIT_SECONDS`。npm 发布需用户单独批准。

当前生产为关闭旧写流程的框架，systemd 必须设置：

```text
MODEL_VERITY_V2_EXPLORATORY_DEFAULT=1
```

默认 SSRF policy 会拒绝 DNS 解析到 loopback、私网、link-local 和保留地址的供应商 endpoint。仅本地开发 mock 可显式设置：

```text
MODEL_VERITY_ALLOW_PRIVATE_ENDPOINTS=1
```

生产不应设置该变量。部署脚本候选 smoke 不调用供应商，因此不需要放宽。

## 6. 数据目录

| 路径 | 内容 |
|------|------|
| `~/.config/model-verity/db.sqlite` | providers、验证运行、结构化 observations/evidence、reference governance、预算和分享报告 |
| `~/.config/model-verity/secrets/` | 加密后的 key 材料（非明文） |
| `~/.config/model-verity/runs/<id>/` | 可选 raw 响应（S3 开关） |

Linux 遵循 XDG 时可能映射到 `$XDG_CONFIG_HOME/model-verity`。

**备份**：复制整个配置目录；恢复前注意权限 `700`。  
**卸载残留**：`npm remove -g model-verity` **不会**自动删除数据目录，需手动删。

## 7. 安全运维要点

1. 本地使用和当前反代部署都只绑定 `127.0.0.1`，不要绑定 `0.0.0.0`。  
2. 日志与导出默认无 API Key；分享报告前检查。  
3. Preview Lab（`npm run preview:ui`）不加载真实 key。  
4. 本机 root/恶意进程仍可能读加密文件——威胁模型是防误泄露，不是防本机攻击者。

## 8. 典型使用流程

```text
1. model-verity start
2. 浏览器打开 → 供应商：添加目标或参考 endpoint
3. 验证：选择“参考样本比对”或“实时双端配对”
4. 确认两端协议、产品面、参考等级和最大请求/token 预算
5. 查看评分、行为、来源、稳定性、协议和时效证据；内置参考比较使用固定 PAMELA prompt，实时配对/自建参考使用 marked prompt
6. 如需重复使用可信基线，在“参考样本”创建 L2/L3 自建参考，明确批准 20/80/240 次请求预算；质量门禁通过后自动进入验证下拉
7. 在历史记录导出或删除结果
8. Ctrl+C 停止
```

## 10. 故障排查

| 现象 | 处理方向 |
|------|----------|
| 端口占用 | `--port` 换端口；`status` 查旧进程 |
| keytar 失败 | 回退文件加密；安装 libsecret（Linux） |
| 429 频繁 | 等待供应商限流窗口恢复，改用较低预算档位；系统不会自动重试或扩大预算 |
| 全 failed | 查 baseUrl/key/协议是否选错 |
| 永远 inconclusive | 查 reference 是否覆盖 cells；n 是否过低；reasoning 是否关失败 |
| 内置参考加载失败 | 检查 npm 包内 `dist/data/builtin-fingerprints.json.gz` 是否存在且完整 |
| 内置模型找不到 | 在 References 搜索完整 OpenRouter model slug；库仅纳入满足 40-cell/有效样本门槛的 146 个模型 |
| 官方模型对内置参考分数不高 | 先确认内置参考是特定 OpenRouter/upstream/snapshot/采集时点，不是统一官方认证；检查 JSD、P3、L3、时效和 calibration。用修正后的 Audit 复测，必要时用 Full、同协议 L2 自建参考或 L1 官方直连配对；不得直接改权重或删高 JSD cell |
