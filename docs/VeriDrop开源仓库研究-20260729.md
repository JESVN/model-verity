## 2. VeriDrop 验证流程

1. 用户选择 Claude/OpenAI/Gemini 协议页。
2. 填 base URL、临时 Key、模型和 quick/standard/full。
3. Runner 按 mode 和 model capability 筛选 detector。
4. Active detector 主动发 identity、thinking、tool、structured output、stream 等请求。
5. Passive detector 订阅 active 请求的原始响应，复用它们检查协议字段和 ID。
6. 每个 detector 返回 0–100、weight、status、details 和 error。
7. `skip` 项不进入加权分母。
8. 总分按有效权重归一化。
9. critical issue 单独设置 verdict cap，避免高均分覆盖关键失败。
10. 报告首屏显示总分、等级和检测项；详细字段折叠。

## 3. 协议差异

### Anthropic

重点包括 identity、behavioral signature、thinking signature、consistency、knowledge、PDF、tool use、protocol、integrity、token usage、message ID 和可选长上下文。

thinking signature 是其最强项，但源码默认只检查：

- thinking/redacted thinking block 是否存在；
- signature 是否非空；
- 长度是否至少 50。

默认实现没有对 signature 做密码学本地验签；DESIGN 提到可通过回传给官方 API 做严格验签，但当前 detector 代码按存在性/长度评分。因此“加密级”表述应区分“观察到官方格式的签名产物”和“完成端到端可验证回执”。

### OpenAI

重点是 basic request、response model、function calling、structured output、协议形状、stream/non-stream、token billing 和可选长上下文。OpenAI 没有对应的通用签名，源码也将其 tier 降为行为/协议级。

### Gemini

重点是基础响应、model info、function calling、structured output、协议、integrity 和 usage，属于协议级。

## 4. 评分逻辑

```text
total = Σ(score × weight) / Σ(effective weight)
```

阈值：

```text
≥70 passed
50–69 marginal
<50 failed
```

UI 再将 passed 中的 ≥85 显示为优秀。README 中写作 ≥85 优秀、70–84 通过、50–69 基本合格、<50 未达标。

关键设计不是阈值，而是：

```text
critical issue 独立于加权分
```

例如 OpenAI usage 暴露 Anthropic 后端痕迹，即使其他结构检查高分，verdict 最多 marginal。

## 5. 优点

- 用户操作路径短，结果信息层级清晰。
- detector 输出统一，可组合、可测试。
- Active/Passive 响应复用减少额外请求。
- skip normalization 适合“能力是否适用”的检测项。
- critical cap 防止平均数掩盖严重问题。
- 报告同时保留总分和字段证据。
- 协议 tier 区分 Claude 与 OpenAI/Gemini 的证据强度。

## 6. 局限与误判风险

- identity 自报可由 prompt 包装伪造。
- response model、ID 前缀和字段形状可由中转站合成，主要证明兼容性。
- knowledge/cutoff 题受幻觉、题库污染和模型更新影响。
- 低温输出 token CV 不是可靠模型身份指标；长度变化可来自 serving stack。
- stream/non-stream 差异可能来自采样和 reasoning，不必然是替换。
- 固定权重和 70/50 阈值未展示独立 FAR/FRR 校准。
- skip 后重新归一化可能让缺失关键检测的协议拿到过高总分；只有配合 tier 和 cap 才安全。
- Claude signature 默认只是格式观察，不应扩展为所有协议的通用来源证明。
- 长上下文探针成本高，不适合静默加入普通验证。

## 7. 对 model-verity 的取舍

### 采用

- 评分优先的结果信息层级。
- 公开维度和权重。
- 结论 cap 与原始数值分分离。
- 技术详情默认折叠。
- 未来新增协议被动检查时复用现有 observation/raw metadata，不额外请求。

### 不采用

- 不用 identity/knowledge/model 字段取代 PAMELA。
- 不把协议兼容高分写成模型真实性。
- 不复制 detector、题库、权重或模板。
- 不静默添加 thinking、PDF、tool use 或长上下文付费请求。
- 不采用 skip 后对核心行为分重新归一化；没有 JSD 时直接无法评分。

## 8. V3 最终融合

model-verity V3 保持 PAMELA/Zenodo 核心：行为一致性 55%，其余请求质量、短时稳定性、可比性和参考强度共 45%。采用 continuous JSD display mapping、明确未校准状态和 critical cap。结果首屏变成分数、等级、三条原因和五个评分条；原始五维与统计证据折叠。

这实现了“更容易理解”，但没有把可读性包装成统计确定性。
