# model-verity — 当前产品与实施方案

> 状态：生产运行中 · 2026-07-28  
> 包名：`model-verity`  
> 生产：`https://modelverity.example/`  
> 形态：CLI + Node API + React Web + SQLite

## 1. 产品定位

model-verity 用于验证第三方 AI 服务的综合声明。系统不输出单一“真假概率”，而是分别表达：

1. 行为一致性；
2. 来源证据；
3. 服务稳定性；
4. 协议可比性；
5. 参考时效。

主要用户是使用中转、聚合、企业 deployment 或其他非官方入口，需要检查模型行为和服务质量的人。

系统不宣称：

- 厂商官方认证；
- 密码学来源证明；
- 返回 `model` 字段足以证明身份；
- 行为近邻等于真实模型身份；
- 一次运行能保证未来持续表现；
- 当前已经达到预注册的 1%/1% 强结论错误目标。

## 3. 验证方式

### 3.1 参考样本比对

- 使用版本化研究参考；
- 对目标 endpoint 运行固定 challenge；
- 计算原始 cell JSD、平均 JSD、有效性和稳定性信号；
- 只支持行为比较，不提升来源等级；
- 参考过期、产品面 unknown、协议不可比或 calibration 缺失时降低结论覆盖。

### 3.2 自建参考样本

- 从角色为 reference/either 的用户可信 endpoint 采集；
- 使用当前版本化 challenge、结构化 observation、attempt 和原子预算；
- 逐批批准 20/80/240 次请求，0 自动重试；
- 质量门禁通过后原子发布不可覆盖的 cohort/version；
- 自动接入参考样本比对；
- 用户路径只允许 L2/L3，不自行升级为 L1；
- stale/review_required/quarantined/superseded 不进入可用列表。

### 3.3 实时双端配对

- Target 与 reference 使用字节一致的 challenge；
- Pair 内近同时启动并随机安排先后；
- 保存真实启动间隔；
- P1 要求严格同协议；
- P2 表示语义映射；
- P3 只作不可比条件下的诊断；
- 临时第一方凭据默认只存在内存。

## 4. 身份和参考模型

身份分层：

```text
Vendor
Product
Surface: api | chatgpt | codex | enterprise | unknown
Snapshot
```

声明、直接观测和规则推断分开保存。推断不能覆盖声明或提升来源等级。

参考等级：

```text
L1：锁定官方 endpoint 的第一方直连
L2：用户指定可信 deployment
L3：研究、社区或本地参考
```

参考版本不可覆盖；质量和时效变化使用 append-only governance event。

## 5. 统计框架

保留：

- 每 cell base-2 JSD；
- 未加权平均 JSD；
- valid/invalid/refusal/empty/error；
- success rate、p50/p95；
- response model 分布；
- bootstrap/conformal evidence；
- impostor acceptance risk；
- block/retry stability evidence。

原始 JSD 是效应量，不单独产生身份结论。

正式强结论长期目标：

```text
行为支持的 impostor 误接收率 ≤ 1%
明显异常的 genuine 误拒绝率 ≤ 1%
```

当前真实矩阵尚未证明该目标，因此生产不得输出未经支持的确定性强结论。

## 6. Runner 与预算

- Challenge manifest 本地确定生成、版本化和内容寻址；
- Pair 是调度单位；
- Target/reference protocol 分别固化；
- Attempt append-only；
- 失败不被重试覆盖；
- 429、网络和上游错误不会自动扩大预算；
- 请求和 token 使用 SQLite transaction 原子记账；
- Token 超限记录最新 usage 后停止后续请求；
- 取消和服务重启不自动重发真实请求。

## 7. 安全与隐私

- 持久 Key 使用 keychain 或 AES-256-GCM 加密文件；
- 临时第一方 Key 只存在内存；
- Key 不进入 SQLite、History、日志、报告或导出；
- 默认不保存完整响应正文；
- Base URL 禁止 userinfo、query、fragment；
- 请求禁止 redirect；
- DNS 解析后拒绝私网、loopback、link-local、CGNAT 和保留地址；
- 禁止 Authorization、Cookie、Host 等危险 header 覆盖；
- 报告只暴露 endpoint hash、config revision 和隔离后的 credential-scope HMAC。
