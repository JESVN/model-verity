## 1. 目标与不可越界边界

### 1.1 产品目标

验证第三方中转站的**综合服务声明**，不再输出单一“可信度”。结果拆为：

1. **行为一致性**：目标 endpoint 的条件输出分布是否与目标产品的校准参考相容。
2. **来源证据**：参考和上游来源证据达到什么等级。
3. **服务稳定性**：是否存在波动、多路 serving、条件 fallback 或动态路由。
4. **协议可比性**：两侧 API schema、产品面、prompt、参数及上下文是否严格可比。
5. **参考时效**：reference 是 current、usable、stale、review required 还是 quarantined。

综合摘要只总结这些证据，不将 JSD、conformal p-value 或任一指标表述为“模型为真的概率”。

### 1.2 强结论错误目标

正式框架预注册目标：

```text
“行为支持”的 impostor 误接收率 ≤ 1%
“明显异常”的 genuine 误拒绝率 ≤ 1%
其余结果进入“需要复核”或“不可验证”
```

若某模型、产品面、协议或 profile 达不到目标：缩小适用范围、增加预算或降低结论覆盖率，不放宽强结论错误目标。任何未来目标变更必须成为新的 framework major version，并重新划分开发集和冻结验收集。

### 1.3 不做的声明

- 不宣称厂商官方认证。
- 不宣称密码学来源证明。
- 不从返回 `model` 字段单独认定身份。
- 不因一次历史参考偏离指控模型替换或欺诈。
- 不把 Chat、Responses、ChatGPT、Codex、Enterprise 或 Unknown 产品面自动视为等价。
- 不用看过冻结验收结果后调整阈值并在同一数据上宣称通过。

## 3. 验证模式

### 3.1 研究参考探索性筛查

适用于没有第一方凭据或产品面未知的场景：

- 使用版本化固定 battery 和 reference cohort。
- 输出最多为“行为与目标产品相容”或“相对已知参考偏移，需要配对验证”。
- 不提升来源证据。
- 参考过旧、产品面 unknown、协议不严格可比或 calibration 缺失时不得给红色强异常。
- PAMELA `main-02` 保留为 Tier 3 研究 gallery，不再单独承担当前官方产品验证。

### 3.2 Tier 1 官方维护 cohort

首版支持标准 OpenAI 官方 API 产品面：

- 参考不可变、版本化、内容寻址。
- 至少两个预注册观测窗口；首版允许同一会话内随机交错 block。若没有跨日窗口，长期稳定性必须标为 `not_assessed`，不能输出未来持续保证。
- 固化 catalog alias、reported snapshot、surface、protocol、provider、采集时间、请求 manifest、采集工具版本和质量报告。
- 不后台静默更新；随 reference package 版本发布。
- 首版模型使用冻结 allowlist：GPT-5.5 目标、可获得的精确 snapshot、近邻型号/变体及至少一个远端阴性。
- Codex、Review、Thinking、Agentic 等特殊产品面默认隔离，不自动加入标准 API cohort。
- 具体 allowlist 与真实采样预算须在采样前再次提交用户批准。

### 3.3 用户第一方实时配对

用于最高强度行为证据：

- 第一方与中转站对同一 challenge 近时间、随机顺序、交错采样。
- P1 严格同协议可产生最高等级配对行为证据。
- P2 语义映射协议结论降一级。
- P3 不可比协议只做服务诊断。
- 第一方实时配对优先于历史 cohort，但仍不是密码学来源证明。
- 临时第一方凭据为默认；运行结束后删除引用，不落 SQLite、History、导出或日志。
- 持久第一方凭据仅用户明确启用，并提示主机失陷风险。

## 4. 身份、参考与协议模型

### 4.1 分层身份

```text
VendorIdentity   例如 OpenAI
ProductIdentity  例如 GPT-5.5 rolling product
SurfaceIdentity  api | chatgpt | codex | enterprise | unknown
SnapshotIdentity 例如 gpt-5.5-20260423，可为空
```

特殊变体 `mini/nano/chat/codex/review/thinking` 默认独立，不经 calibration 证明不得合并。

### 4.2 声明、观测、推断分离

每个模型映射保存：

```text
declared：用户或中转站声明
observed：requested/response model、协议、response object、usage 等直接观测
inferred：规则产生的弱候选及规则版本
```

自动推断不能覆盖声明、提升来源等级或进入强结论。未经可靠元数据确认时 `surface=unknown`。

### 4.3 参考等级

```text
L1 官方直连：系统锁定官方 endpoint 和规则
L2 用户信任 deployment：Azure、企业或账号产品面，信任由用户声明
L3 研究/社区/本地参考：只支持筛查或稳定性分析
```

### 4.4 协议可比等级

```text
P1 严格同协议：schema、字段和角色结构一致
P2 语义映射：例如 Responses ↔ Chat，只能降级结论
P3 不可比：工具、Agent、搜索、强制 reasoning 或隐藏产品上下文
```

adapter 禁止在同一 run 中静默切换协议。协议失败必须结束 run，由用户重新确认。

### 4.5 Reference cohort

- 每个 reference version 不可变。
- cohort 管理成员状态，不覆盖成员数据。
- 状态拆分：
  - `identityStatus`: exact | rolling | unknown
  - `freshnessStatus`: current | usable | stale
  - `qualityStatus`: approved | review_required | quarantined | superseded
- Exact snapshot 可长期用于指定历史 snapshot 验证；其 behavior freshness 仍单独展示。
- Rolling product 默认 freshness 建议：0–14 天 current、15–45 天 usable、超过 45 天 stale；厂商 policy 可覆盖。
- reported snapshot 变化、质量失败或行为 heartbeat 异常可立即 review/quarantine。
- cohort 采用 robust aggregation，不能简单取所有 reference 的最小距离。

## 5. 统计框架

### 5.1 保留原始指标

继续计算并展示：

- 每 cell base-2 JSD；
- 未加权平均 JSD；
- valid/invalid/refusal/empty/error；
- success rate、p50/p95；
- reported model/snapshot 分布。

原始 JSD 只作为可审计效应量，不再由固定 `0.12/0.22` 单独产生正式结论。

### 5.2 校准证据

每次正式 run 计算：

```text
observed distance
expected genuine distance
finite-sample posterior predictive / bootstrap distribution
genuine conformal p-value
impostor empirical distribution
impostor acceptance risk
standardized cell and aggregate evidence
```

任何 `p` 都必须命名为 tail probability 或 conformal p-value，不称“模型为真的概率”。

### 5.3 校准维度

至少按以下维度版本化：

- vendor/product/surface；
- protocol comparability；
- Quick/Audit/Full 或 paired budget；
- cell family/subset；
- nRef/nAudit；
- same-provider/cross-provider/cross-surface；
- reference freshness；
-并发和重试策略。

没有匹配 calibration artifact 时输出 `uncalibrated`，不得产生强结论。

### 5.4 Cell 分层

每个 cell 保存：

```text
genuine variance
cross-provider variance
impostor separation
entropy
validity rate
surface sensitivity
time stability
information score
```

类别：

- Core：主结论。
- Discriminative：增强阴性证据，不能单独标红。
- Diagnostic：影响可比性和稳定性，不直接决定身份档位。
- Excluded：质量或校准不足。

主聚合使用预注册的 shrinkage、方差标准化或 robust weighted mean；权重由 calibration 固化，不能按单次结果调整。原始未加权 JSD 始终保留。

### 5.5 多维结论

```text
行为一致性：支持 | 合理漂移 | 需要复核 | 明显异常 | 未校准
来源证据：未验证 | 用户声明参考 | 第一方配对支持 | 可验证回执
服务稳定性：稳定 | 波动 | 可能多路 serving | 疑似条件 fallback | 数据不足
协议可比性：严格可比 | 语义可比 | 不可比
参考时效：current | usable | stale | review_required | quarantined
```

强结论：

- “行为支持”需符合 impostor 误接收 ≤1%、质量/协议门禁和参考时效。
- “明显异常”需 genuine 误拒绝 ≤1%，且重复运行、内部稳定性和对照条件成立。
- 单次研究参考偏离只输出“需要复核”。
- 无法达到门槛时不得强制二分。

### 5.6 阳性、阴性与邻域证据

配对 run 同时分析：

```text
D_ref_internal
D_proxy_internal
D_cross
```

- 两端内部低、跨端高，才支持系统性偏移。
- 历史 gallery 为 N1 弱阴性对照。
- 用户明确授权的实时不同模型为 N2 强阴性对照。
- 不自动调用付费阴性模型。
- 最近邻只显示“行为邻域”，默认折叠；不能写“实际模型是 X”。

### 5.7 动态路由检测

按 reported model、时间、latency、usage、attempt、error 和答案分布检测：

- metadata change point；
- behavioral mixture；
- retry/fallback 条件关联；
- block/window drift。

单个 `model` 字段变化不决定结论。动态路由和行为一致性独立展示。

## 6. Paired Challenge Runner

### 6.1 Challenge 生成

使用本地、确定性、版本化模板语法。当前 manifest 为 `pamela-challenge@2`，显式记录 `promptMode`：

```text
fixed：人工审核前缀 + 任务表达 + 格式约束
marked：人工审核前缀 + 任务表达 + 格式约束 + 无语义 marker
```

约束：

- 两端 system/user 字节完全相同。
- variant 有 ID、版本和内容 hash。
- 生成器不调用外部 LLM。
- variant 在多个可信 deployment 上校准后才进入正式 pool。
- 显著改变基线的 variant quarantine。
- PAMELA 固定 prompt 用于内置研究参考比对，与 Zenodo 采集协议一致。
- marked variant 只用于实时配对和自建参考；两端或参考版本与后续目标必须使用相同协议。
- 服务端按 block 生成，运行开始后固化 challenge manifest；manifest 必须保存 `promptMode`。

### 6.2 序贯 block

建议结构，最终数值由 calibration 冻结：

```text
Block 1：4 cells × 5 reps × 2 endpoints
后续 block：增加新 cells/repetitions
达到预注册强结论或最大预算后停止
```

- 用户启动前批准最大 pair/request/重试预算。
- 自动停止只减少费用，不能自动追加预算。
- 达到最大预算仍重叠则“需要复核”。
- 停止条件写入 manifest，运行中不可修改。

### 6.3 Pair-aware 并发

- 调度单位为 pair。
- 默认最多 2 个活跃 pair；高强度或会话状态敏感 surface 为 1。
- 两端 endpoint 分别限流。
- pair 内启动顺序随机，记录实际 time gap。
- calibration 必须匹配并发策略。
- 429 只暂停对应 endpoint；不能让另一端提前跑完整个队列。

### 6.4 失败和重试

- 所有 attempt append-only 保存，重试不能覆盖首次失败。
- 仅网络、408、429、5xx 按预注册策略重试。
- reasoning 控制不兼容只允许 adapter 回退一次并标记降级。
- 行为主分析使用每侧第一个有效响应；禁止看答案后选 attempt。
- 只有两侧均有效且 time gap 合格才进入最高等级跨端分析。
- 单侧 observation 仍进入该 endpoint 的内部稳定性和服务质量。
- replacement pair 使用新 challenge ID；失败 pair 永不删除。
- 报告计划/完整 pair、首次/最终成功率、重试、replacement 和时间差。

### 6.5 预算授权

每批真实测试先生成计划：

```text
供应商、模型、协议、场景、最大 pair、最大请求、最大重试、费用估算、有效期
```

用户批准后产生不可扩大的 budget token。执行器必须服务端强制校验。CI、build、部署和普通自动测试永不调用真实供应商。

旧表 `runs`、`reference_fingerprints` 永久只读。新增建议表：

```text
model_identities_v2
provider_model_mappings_v2
reference_cohorts_v2
reference_versions_v2
reference_governance_events_v2
calibration_profiles_v2
calibration_artifacts_v2

challenge_manifests_v2
challenge_blocks_v2
challenge_observations_v2
observation_attempts_v2
verification_evidence_v2
verification_conclusions_v2
verification_series_v2       # 仅预留，不启用自动哨兵
share_reports_v2
budget_authorizations_v2
```

### 7.1 关键约束

- reference version、observation、attempt 和 conclusion revision 不可覆盖。
- 重新分析产生新 evidence/conclusion revision。
- conclusion 固化 framework、calibration、gallery、cell pool 和 policy 版本。
- reference version 被 run 引用时只允许归档，不允许物理删除。
- 删除 run 删除专属 observation、raw、evidence、conclusion、分享报告和缓存，不删除共享 calibration/reference。
- History 聚合 API 始终返回 `frameworkVersion`、record type 和 legacy 标记。

### 7.2 Observation 默认保留

保存：

- challenge/variant/block/pair ID；
- request body hash；
- endpoint role、协议和 adapter 版本；
-规范化类别和 validity；
-时间、顺序、latency、usage；
- reported model/snapshot；
- reasoning 状态；
- HTTP/error 分类和 attempt；
- response object 类型。

默认不保存：

- API Key、Authorization、Cookie；
-完整 request headers；
-完整敏感错误 body；
-完整 raw response。

单词/数字可见回答默认可保留；超长、疑似 secret/个人信息或异常回答只保存 hash、长度和脱敏摘要。完整 raw 默认关闭；诊断模式默认 TTL 7 天，导出 raw 需再次确认。

## 8. 密钥与安全

### 8.1 第一方凭据

- 默认临时会话内存使用。
- 不写磁盘、SQLite、History、日志或导出。
- 服务重启后 paired run 失败，要求重新授权。
- 持久模式需二次确认；Linux production 优先 systemd credentials、Vault 或外部 secrets manager。
- 第一方和中转凭据使用独立类型、权限和生命周期。

### 8.2 Endpoint 与 SSRF

L1 官方 endpoint 锁定 origin、协议和重定向策略。L2/中转 endpoint 延续并加强：

- 禁止敏感 scheme、userinfo 和危险重定向；
- DNS rebinding/私网地址按部署 policy 管理；
- headers allowlist，禁止 Authorization/Cookie/Host 覆盖；
- 错误和日志递归脱敏；
- 请求 body 不进入反向代理访问日志。

### 8.3 报告绑定

报告绑定：

- canonical endpoint display 和 origin hash；
- provider config revision；
- credential scope HMAC；
- requested/observed/reference identity；
- protocol、surface 和时间窗口。

永不包含 query、fragment、userinfo 或 Key。配置或 credential scope 变化后旧报告显示“配置已变更”。

## 12. 测试矩阵

### 12.1 Core statistics

- JSD 对称、有界、相同分布为 0。
- Dirichlet/bootstrap 固定 seed 可复现。
- conformal p-value 有效范围和经验覆盖。
- finite-sample 高熵 cell 不被当作零噪声。
- Core/Discriminative/Diagnostic 聚合隔离。
- Calibration artifact hash/版本不匹配时拒绝强结论。
- FAR/FRR 和 coverage 报告可从冻结 artifact 重建。

### 12.2 Runner

- 两端 challenge 字节/hash 相同。
- pair 顺序随机但 seed 可复现。
- 并发不超过 pair/endpoint 上限。
- 首次失败不被重试覆盖。
- replacement 不删除失败 pair。
- time gap 降级。
-取消、超时、服务重启和网络中断。
- budget 不可突破，重试也计费。
-一侧持续失败只产生基础设施结论。

### 12.3 Identity/reference

- alias、product、surface、snapshot 不自动合并。
- inferred 不覆盖 declared。
-L1 endpoint 规则不可由用户伪造。
-L2/L3 不能提升为来源已验证。
-stale/quarantined 限制结论。
-cohort 异常 member 不扩大接受区。
-旧 reference 永不进入 v2 正式验证。

### 12.4 Security/privacy

- 临时 Key 不落 SQLite、磁盘、日志、错误、History、导出。
-SSRF、redirect、DNS、header 覆盖和 host policy。
-错误摘要递归脱敏。
-raw TTL 和删除。
-分享报告不暴露 Key、query、内部 host 或 credential cross-site identifier。
-公式注入防护延续到 v2 CSV。

### 12.5 UI/E2E

-开发暂停态不可从 Web 启动 Audit/Enrollment。
-配对预算确认、协议等级和来源等级可读。
-运行恢复、多标签页和取消。
-五维结论不会压缩成可信度。
-红色仅强异常。
-Legacy 历史明确且不重算。
-320–430px 无溢出；键盘、焦点、reduced motion。
-报告过期和配置变更状态。

### 12.6 真实验收矩阵

阳性：

- 同一官方 endpoint 重复。
-同一中转路径重复。
-同模型不同预注册 block/观测窗口；跨日窗口为可选增强证据，不是首版硬门禁。
-同模型 Chat↔Chat、Responses↔Responses。
-已知同模型不同 serving stack。

可比性降级：

-标准 API↔Codex/ChatGPT。
-Chat↔Responses。
-精确 snapshot↔rolling alias。
-current deployment↔stale reference。

阴性：

-目标↔已知上一代旗舰。
-目标↔mini/nano。
-目标↔其他厂商。
-稳定替代、block 混合和条件 fallback。

## 13. 发布验收标准

### Engineering Gate

- 全部 typecheck、单元/属性/集成/迁移/API/浏览器 E2E 通过。
-生产 build、dependency audit、pack 和独立安装通过。
-中断恢复、预算、删除、TTL、导出和旧 API sunset 通过。

### Statistical Gate

- artifact 可重建且 hash 一致。
-开发集与冻结验收集分离。
-强异常 genuine 误拒绝 ≤1%。
-行为支持 impostor 误接收 ≤1%。
-同时报告强结论 coverage、需要复核率和不可验证率。
-跨产品面、unknown、stale、uncalibrated 不错误标红。

### Security/Cost Gate

-临时第一方 Key 不落盘。
-budget token 不可超支。
-真实请求均有批次授权。
-SSRF/redirect/header/log/export/share 安全测试通过。
-测试结束无活跃任务和遗留凭据会话。

### Real Provider Gate

-冻结真实矩阵通过。
-每批实际请求数、usage、费用和停止原因可审计。
-目标 genuine、impostor、跨 surface 和动态路由场景均有记录。

### UI Review #006

人工检查：

1. 当前 UI 不显示内部版本、迁移、暂停或 Legacy 标签。
2. 五维结果和综合摘要不使用伪可信概率。
3. 来源、surface、snapshot、协议和 freshness 易读。
4. 第一方临时 Key、费用和预算清晰。
5. 运行、取消、恢复和失败反馈完整。
6. 全新 History 空状态和新记录删除正确。
7. 分享报告范围、时间、过期和限制不可隐藏。
8. 移动端、键盘、焦点和 reduced-motion 通过。

生产框架已按用户批准完成替换；Review #006 已于 2026-08-03 Approved。UI 验收不放宽 Statistical Gate。
